# Upcoming Mobile Features Technical Specification

This document outlines the technical specifications, data structures, and implementation logic for upcoming mobile features in the React Native application (`sawitin`).

---

## 1. Local Database Migration (SQLite & WatermelonDB)

### Objective
Upgrade the current state store synchronization (`useSyncQueueStore` and `useSyncProcessor`) to a persistent relational local database to handle thousands of offline records safely.

### Implementation Blueprint
- **Library**: `WatermelonDB` (built on top of `SQLite` with lazy-loading capabilities).
- **Schema Mapping**:
  - `bkm_panen` table (links to local block boundaries, dates, statuses).
  - `bkm_panen_details` table (links to worker IDs, grading metrics, local photo paths).
  - `sync_queue` table (tracks pending actions, endpoints, JSON payload values, and retry counters).
- **Offline Flow**:
  - Local queries fetch data directly from SQLite instead of network requests.
  - CRUD operations write to SQLite locally, updating UI states instantly.

## 2. Advanced Vision Camera QR Scanner (`scan.tsx`)

### Objective
Implement a high-speed camera scanning screen for Krani Timbang to decode the SPB barcode generated by foremen checkers.

### Core Configurations
- **Library**: `react-native-vision-camera` + `vision-camera-code-scanner`.
- **Brightness Controller**:
  - Toggles the screen brightness automatically to 100% when entering the scanning viewport to optimize contrast.
  - Reverts screen brightness to system defaults upon leaving the screen.
- **Torch Controller**:
  - Direct toggle button on the screen header to activate/deactivate the camera LED flash.
- **Decoding Signature**:
  - Decodes flat deliminated string payloads (`${tphId}|${quantity}|${timestamp}|${signature}`) and verifies signatures before calling backend REST APIs.

## 3. GPS Block Geofencing Verification

### Objective
Validate that the foreman or harvester is physically standing within the coordinates of the designated Block when logging crew attendance or harvest deposits.

### Core Hook Configurations
- **Library**: `expo-location` (Runs in the foreground/background).
- **Database Boundary Mapping**:
  - Block schemas must include boundary coordinate arrays (Polygons).
- **Verification Logic**:
  - Hook retrieves coordinate properties: `latitude`, `longitude`, and `accuracy`.
  - Runs a **Point-in-Polygon (PIP)** calculation checking if coordinates are within the target block boundary polygon.
  - If coordinate deviation exceeds block margins, it prompts a verification warning box.

## 4. ESC/POS Bluetooth Thermal Printing

### Objective
Equip Krani Timbang at the weighbridge with the capability to print physical scale ticket receipts directly from their mobile phone to handheld thermal printers via Bluetooth.

### Integration Blueprint
- **Library**: `react-native-bluetooth-escpos-printer`.
- **Data Payload**:
  - Pulls weight details from `useKraniTimbangStore` header: loaded weight, empty weight, net yield, driver, and vehicle plate.
- **Ticket Command Formatting**:
  ```plaintext
  ESC/POS Commands:
  [Initialize Printer]
  [Set Align: Center] -> "SAWEED PLANTATION GROUP"
  [Set Align: Left]   -> "Scale Ticket: #KT100938"
                         "Transporter : BP 1289 XY"
                         "Driver      : Budi Santoso"
                         "Gross Weight: 8,400 kg"
                         "Tare Weight : 4,100 kg"
                         "Net Yield   : 4,300 kg"
  [Feed Paper & Cut]
  ```
- **Connection Handshake**:
  - Renders a modal prompting available BLE devices nearby.
  - Connects, sends byte streams, and caches printer MAC addresses for automated reconnects.
